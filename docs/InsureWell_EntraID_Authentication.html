InsureWell — Authentication with Microsoft Entra ID

Change documentation · React 18 SPA + Spring Boot 3.1 API

Issue: “Implement Authentication with Azure AD” — use Microsoft Entra ID and the latest Microsoft Identity features.

1. Summary of the change

InsureWell now authenticates users with Microsoft Entra ID (formerly Azure AD) on the Microsoft identity platform v2.0 endpoint. The React SPA signs users in with MSAL (@azure/msal-browser and @azure/msal-react) using the authorization code flow with PKCE, and attaches the resulting access token to every API call. The Spring Boot API is an OAuth 2.0 resource server that validates the token signature against the tenant JWKS endpoint and checks the issuer and audience claims before serving policy or claim data.

  • No passwords, secrets or tokens are stored by InsureWell; tokens live in sessionStorage only.
  • App roles (roles) and delegated scopes (scp) are mapped to Spring Security authorities, ready for fine-grained authorisation.
  • Authentication is configuration-driven: with no tenant configured the app keeps running unauthenticated for local development against the seeded H2 data.

2. Authentication flow

Browser (React SPA)                Microsoft Entra ID                 InsureWell API
      |                                    |                                  |
      |-- loginRedirect (PKCE) ----------->|                                  |
      |<-- id_token + code ----------------|                                  |
      |-- acquireTokenSilent ------------->|                                  |
      |<-- access_token (aud = API) -------|                                  |
      |-- GET /api/policies  Authorization: token ---------------------------->|
      |                                    |<-- JWKS (signature keys) --------|
      |<-- 200 policies / 401 invalid token ----------------------------------|

6. Verification

  • SecurityEnabledTest — public health endpoint stays open, policies/claims/me return 401 without a token, and /api/me returns the token claims with one.
  • SecurityDisabledTest — with mode=off the API stays open for local development.
  • EntraIdSecurityUnitTest — audience validation, issuer/JWKS URI derivation and role/scope mapping.
  • Manual run: with tenant and client id set, GET /api/policies returned 401 with a WWW-Authenticate challenge; without them the seeded data still loads.
  • Frontend production build compiles successfully with and without the Entra ID environment variables.

7. Entra ID app registration checklist

  • Register an API application; expose a scope such as access_as_user.
  • Register the SPA application with platform “Single-page application” and redirect URI http://localhost:3000 (plus the deployed origin).
  • Grant the SPA delegated permission to the API scope and admin-consent it.
  • Optionally define app roles (for example Claims.Approve) — they arrive as ROLE_* authorities.
  • Set the backend and frontend environment variables listed above.
